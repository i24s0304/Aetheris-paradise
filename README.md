# Drift Paradise — заявки в команду

Сайт подачи заявок на вступление в команду сервера **Drift Paradise** с админ-панелью для рассмотрения заявок.

## Возможности

- **Публичная форма** — ник, контакт для связи (Telegram/Discord), количество часов на сервере.
- **Админ-панель** — вкладка на главной странице, вход по паролю, список заявок, фильтры по статусам, «принять / отклонить», «удалить».
- **Два режима хранения** — облачная БД (PostgreSQL/Supabase) либо локальный JSON-файл. Переключается автоматически по наличию `DATABASE_URL`.
- **Авторизация** — сессионные токены с TTL 7 дней.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `3000` | Порт сервера |
| `ADMIN_PASSWORD` | `drift2024` | Пароль администратора (**смени перед публикацией!**) |
| `DATABASE_URL` | *(пусто)* | Строка подключения к PostgreSQL (например из Supabase). Если задана — заявки хранятся в облачной БД |
| `DATA_FILE` | `data/applications.json` | Путь к JSON-файлу (только для локального режима) |

## Запуск локально

```bash
npm install
npm start            # JSON-режим (заявки в data/applications.json)
```

Без `DATABASE_URL` сервер хранит заявки в локальном файле — удобно для проверки:
`http://localhost:3000` — форма, вкладка «Админу» — панель. Пароль по умолчанию `drift2024`.

## Быстрый деплой на бесплатный хостинг

Этот вариант даёт **постоянную ссылку**, по которой игроки могут заполнять заявки с любых устройств. Нужны два бесплатных сервиса:

1. **Supabase** — хранение заявок в облачной БД (переживают перезапуски и не стираются).
2. **Koyeb** (PaaS) — бесплатный хостинг Node-приложения; или **Render** как запасной вариант.

> Важно: чтобы заявки не терялись, **обязательно** сначала создайте БД в Supabase и выполните SQL из `schema.sql`, а только потом деплойте код. Иначе сервер без `DATABASE_URL` упадёт в эфемерный дисковый режим и данные исчезнут при перезапуске.

### Шаг 1. БД в Supabase

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) (бесплатный тариф).
2. Создайте проект.
3. В меню слева: **SQL Editor → New query**. Вставьте содержимое файла `schema.sql` и нажмите **Run**. («Успешно» — таблица готова.)
4. **Project Settings → Database → Connection string**. Скопируйте value строки подключения (для Node.js, вида `postgresql://postgres.XXXX:password@aws-...pooler.supabase.com:5432/postgres`). Сохраните — понадобится в шаге 3.
5. В настройках подключения включите параметр **Connection pooling** (для Koyeb это надёжнее).

### Шаг 2. Код на хостинг (Koyeb)

1. Зарегистрируйтесь на [koyeb.com](https://koyeb.com) (GitHub-аккаунтом или почтой).
2. `Create Service → Create Web Service`.
3. Выберите способ загрузки кода. Проще всего через Git:
   - Залейте содержимое проекта в GitHub-репозиторий (без `node_modules`),
     либо впишите наш открытый образ сборки (для Express это не обязательно).
   - **Buildpack (рекомендуется):** Koyeb сам выполнит `npm install` и запустит `npm start`. Убедитесь, что в `package.json` есть `"start": "node server.js"` (уже есть).
4. В разделе **Environment variables** добавьте:
   - `ADMIN_PASSWORD` = ваш надёжный пароль админа
   - `DATABASE_URL` = строка подключения из шага 1
5. Задеплойте (`Deploy`/`Redeploy`). После сборки вы получите публичную ссылку вида `https://<имя>-<хэш>.koyeb.app`.

Ссылка из шага 5 — это и есть адрес, который можно кидать игрокам. Админ-панель — та же ссылка + вкладка «Админу».

> Koyeb на бесплатном тарифе «засыпает» после ~1 часа без нагрузки и «просыпается» за ~5 секунд при первом запросе. Заявка от первого зашедшего игрока может чуть подождать — это нормально, следующие будут быстрыми.

### Запасной вариант: Render

Если Koyeb не подошёл, то же самое делается на [render.com](https://render.com):
- **New → Web Service** → подключить репозиторий / загрузить код.
- Build command: `npm install`, Start command: `npm start`.
- Env vars: `ADMIN_PASSWORD`, `DATABASE_URL`.
- Бесплатный тариф также «спит» при простое.

## Смена пароля администратора

Пароль по умолчанию — `drift2024`. **Обязательно смени перед публикацией**, задав переменную окружения `ADMIN_PASSWORD` (на хостинге — в env vars, локально — в среде PowerShell с `$env:ADMIN_PASSWORD="..."`).

## API

### Публичные
- `POST /api/applications` — подать заявку. Тело: `{ "nickname": "...", "contact": "@tg", "hours": 120 }`. Ответ `201`. Ошибки: `400` (невалидные данные), `409` (уже есть непросмотренная заявка с таким ником).
- `GET /api/health` — проверка; отдаёт `storage: "database" | "file"`.

### Админские (заголовок `Authorization: Bearer <token>`)
- `POST /api/admin/login` → `{ "token": "..." }`
- `POST /api/admin/logout`
- `GET /api/admin/applications?status=pending|accepted|rejected`
- `POST /api/admin/applications/:id/decide` — `{ "decision": "accepted" | "rejected" }`
- `DELETE /api/admin/applications/:id`
